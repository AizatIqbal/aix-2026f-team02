## Load into MySQL

Run `management_schema_1.sql` first, then load the SQL into an **empty**
database (it uses explicit IDs, so it can't sit on top of `pointnull_mock_data.sql`).
To replace the small sample, drop and recreate `business_management` first.

```cmd
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p < pointnull_mock_data_large.sql
```

## Files

- `pointnull_mock_data_large.sql` - everything above, batched INSERTs in one transaction.
- `csv/categories.csv`, `csv/products.csv` - same catalog as the SQL, in the columns the import wizard maps (`category_name`; `source_product_id, product_name, category_name, price`).
- `csv/customers.csv`, `csv/campaigns.csv`, `csv/orders.csv`, `csv/order_items.csv` - the other tables with DB column names (the wizard doesn't import these yet).
- `csv/products_import_edge_cases.csv` - 32 deliberately awkward product rows for the import wizard: duplicates, blank/invalid/negative/overflowing prices, 100/101-char names, 50/51-char categories, category-as-ID, Hangul, emoji, embedded quotes/newlines, an SQL-injection string, an HTML tag.

## What the data is built to exercise

- **Anonymous orders:** 90% have `customer_phone` NULL; 91% have no `promocode`.
- **Customers:** 75 registered customers, about 10% of orders; gender is 36 Male, 31 Female, 8 unanswered (unanswered = NULL); 8 have no age; known ages run 15 to 60 (including under-18s). 4 never ordered. Ordering habits differ by age and gender, and customers have favourite dishes, so demographics and recommendations show real signal.
- **Products:** 1 never sold (a deliberately zero-demand premium item); 3 launch mid-period (Dalgona Latte 2025-05-01, Mala Tteokbokki 2026-02-10, Honey Butter Chicken 2026-04-01); 3 are seasonal (Cold Buckwheat Noodles: summer, Patbingsu: summer, Hotteok: winter).
- **Price history:** from 2026-03-01 some menu prices rose, so older `order_item.price` can differ from `product.price` (the unit-price snapshot).
- **Calendar gaps:** 13 closed days (holidays, a 3-day renovation closure, random closures) and a few surge days; weekday/weekend and lunch/dinner peaks.
- **Campaigns:** promos are only used inside their date window and by eligible orders (lunch, weekend, first order, loyal, win-back, groups of 3+). Upcoming and expired campaigns have zero orders; two are single-day; three names contain apostrophes (SQL-escaping check).
- **Big baskets:** 101 large party orders; max quantity on one line is 10.
- **Discounts** are fixed KRW amounts (1,000 to 3,000), unlike the 5 to 15 in the small sample file. `total = subtotal - discount`, and a discount never exceeds its subtotal.
